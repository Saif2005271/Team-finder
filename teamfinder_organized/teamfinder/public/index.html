How TeamFinder works

No black boxes. Read what the matcher does, then decide whether you trust it.

A1 The matching algorithm

Each profile contributes a sparse skill vector indexed against the union of all known skills across the platform. Slots not present in a profile are zero; verified skills hold their proficiency level (0–5).

The system computes cosine similarity between your vector and every other student's:

cosine(A, B) =      A · B
              ─────────────────
                |A| × |B|

A small availability bonus (up to +0.05) is added when your weekly hours are close to the candidate's. The result is clamped to [0, 1] and shown as a percentage. The whole thing is deterministic — two identical profile inputs produce identical scores.

A2 Skill exams

Self-reported skills are noise. Every skill on your profile must be earned by passing a short multiple-choice exam stored on the server, so a "Python: Level 4" badge means you got 71–85% on the Python exam — not that you said you were good at it.

Level bands: 0 ≤ 20%, 1 ≤ 40%, 2 ≤ 60%, 3 ≤ 70%, 4 ≤ 85%, 5 > 85%.

A3 The advisor

The Advisor chat is backed by a large language model (a hosted assistant API) when an API key is configured on the server, and falls back to a rule-based responder otherwise. Either way, your profile is sent in the prompt so replies are personalized.

Conversation history is kept client-side and only the last six turns are sent with each message. Messages are not stored after a session ends unless you save them yourself.

A4 Privacy

Other students only see your name, major, shared skills with them, weekly availability, optional bio, and optional GitHub link. Your email is never exposed in match results. Passwords are stored as bcrypt hashes.
